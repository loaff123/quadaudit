# From an area to an auditable result

This tutorial needs the optional solver dependencies. Run it in a fresh directory or give every experiment a new output path.

```sh
python -m pip install '.[solvers]'
quadaudit verify
quadaudit explain beta-014
quadaudit run --case beta-014 --budget 4096 --trace 4096 --output narrow-feature
quadaudit report narrow-feature
```

Open `narrow-feature/report.html`. In the frozen case, the polynomial is nonzero on a very narrow interior support. The exact reference is stored as a rational number and checked independently. The blind track does not reveal the support boundaries to the solver. The split track supplies all polynomial boundaries equally, sharing the same total callback cap.

Look at five different questions:

1. Did the routine return, warn, exceed its evaluation cap, or time out?
2. Does its represented answer meet the requested absolute target?
3. Is the reported error smaller than the exact actual error?
4. Is the configuration inside the routine's documented mathematical scope?
5. Was that target even achievable at the method's output precision?

A zero error estimate deserves inspection. It can accompany an exactly correct answer, an inaccurate answer, or an unresolved reference enclosure. The tool never divides by an arbitrary epsilon to hide that distinction.

The full trace makes sample locations visible. A truncated trace is explicitly labeled; it cannot establish that an unsampled feature was missed. Exact callback values are generated by rational evaluation followed by one rounding and therefore have substantial overhead. This is an evidence walkthrough, not a speed benchmark.

## Export the same mathematical case

```sh
quadaudit export-regression beta-014 --output beta_fixture.py

```

The fixture depends on the Python standard library for its function and exact reference; running its demonstration also needs SciPy. It can be adapted into an upstream regression test, after checking the library's contract and choosing what behavior that test should require.

## Your own finite polynomial case

Use the Python API to construct a Case from contiguous Segment objects with Fraction endpoints and coefficients. Local coefficients are in ascending powers of t=(x-left)/(right-left). The exact evaluator accepts Fraction or integer inputs, not floats. This avoids silently treating an approximate decimal as exact input.

```python
from fractions import Fraction as F
from quadaudit import Case, Segment
from quadaudit.oracle import audit_case

case = Case('square', 'custom', (Segment(F(0), F(1), (F(0), F(0), F(1))),), F(1, 3))
assert audit_case(case)['valid']
assert case.evaluate_exact(F(1, 2)) == F(1, 4)
```

Custom families receive both generic polynomial audits, but no claim of an additional independently derived named-family identity. The JSON input language cannot execute arbitrary code.
